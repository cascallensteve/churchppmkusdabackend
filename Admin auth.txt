## Quick Start

```bash
# 1. Clone and enter project
cd Treasuty-mkusdabackend

# 2. Create virtual environment
python3 -m venv .venv
source .venv/bin/activate

# 3. Install dependencies
pip install -r requirements.txt

# 4. Configure environment
cp .env.example .env

# 5. Run migrations (SQLite is used automatically when DATABASE_URL is not set)
python manage.py migrate

# 7. Seed admin user
python manage.py seed_users

# 8. Start server
python manage.py runserver
```

Server runs at `http://localhost:8000/`

When you run the server locally, the root URL (`/`) shows a **System Running** page with:
- Real-time system status
- Database connection indicator
- Environment mode display
- Quick link to API documentation

## Database Configuration

The app automatically selects the database based on environment:

- **Local development**: Uses **SQLite** (`db.sqlite3`) when `DATABASE_URL` is not set
- **Production**: Uses **Neon PostgreSQL** when `DATABASE_URL` is set

No code changes needed — just set or unset `DATABASE_URL` in your environment.

**Local `.env` example:**
```
SECRET_KEY=change-me-in-production
DEBUG=True
# No DATABASE_URL = uses SQLite
```

**Production `.env` example:**
```
SECRET_KEY=your-secret-key
DEBUG=False
DATABASE_URL=postgres://user:password@host:port/database
```

## Authentication Flow

```
┌─────────────────────────────────────────────────────────────┐
│  1. First Login (Email + Password)                          │
│     POST /api/auth/login/                                   │
│     {"email": "...", "password": "..."}                     │
│     → Response includes "pin_setup_required": true          │
├─────────────────────────────────────────────────────────────┤
│  2. Set PIN (Authenticated)                                 │
│     POST /api/auth/account/set-pin/                         │
│     Authorization: Bearer <token>                           │
│     {"pin": "1234"}                                         │
├─────────────────────────────────────────────────────────────┤
│  3. Subsequent Logins (Email + PIN)                         │
│     POST /api/auth/verify-pin/                              │
│     {"email": "...", "pin": "1234"}                         │
│     → Returns JWT tokens on success                         │
├─────────────────────────────────────────────────────────────┤
│  4. Forgot PIN (Unauthenticated)                            │
│     POST /api/auth/forgot-pin/                              │
│     {"email": "..."}                                        │
│     → Sends PIN reset link to email                         │
├─────────────────────────────────────────────────────────────┤
│  5. Reset PIN (Unauthenticated)                             │
│     POST /api/auth/reset-pin/                               │
│     {"token": "...", "new_pin": "1234"}                     │
│     → Sets new PIN, returns success message                 │
└─────────────────────────────────────────────────────────────┘
```

## API Endpoints

Base URL: `http://localhost:8000/api/auth/`

### Login

#### `POST /login/`

Authenticate with email + password.

**Password Login:**

```json
{
  "email": "cascallensteve@gmail.com",
  "password": "treasury2026"
}
```

**Success Response (200 OK):**

```json
{
  "access": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
  "refresh": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
  "user": {
    "id": 1,
    "email": "cascallensteve@gmail.com",
    "username": "mkusdachurchtreasry",
    "full_name": "MKUSDA Treasury",
    "pin_setup_complete": true,
    "created_at": "2026-08-20T11:56:17.688758Z"
  },
  "pin_setup_required": false
}
```

---

#### `POST /verify-pin/`

Verify PIN and login. Use this after the user has set up their PIN.

**Request:**

```json
{
  "email": "cascallensteve@gmail.com",
  "pin": "0000"
}
```

**Success Response (200 OK):**

```json
{
  "access": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
  "refresh": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
  "user": {
    "id": 3,
    "email": "cascallensteve@gmail.com",
    "username": "mkusdachurch",
    "full_name": "MKUS Treasury",
    "pin_setup_complete": true,
    "created_at": "2026-08-20T15:49:22.388125Z"
  }
}
```

**Error Response (400 Bad Request) - Invalid PIN:**

```json
{
  "detail": "Invalid PIN. 4 attempts remaining.",
  "remaining_attempts": 4
}
```

**Error Response (400 Bad Request) - Account Locked:**

```json
{
  "detail": "Account locked. Try again in 60 seconds.",
  "lockout_remaining": 60
}
```


### PIN Reset

#### `POST /forgot-pin/`

Request a PIN reset link to be sent to the user's email.

**Request:**
```json
{
  "email": "cascallensteve@gmail.com"
}
```

**Response (200 OK):**
```json
{
  "detail": "PIN reset email sent successfully.",
  "email": "cascallensteve@gmail.com"
}
```

**Error Response (400 Bad Request):**
```json
{
  "detail": "No user found with this email address."
}
```

---

#### `POST /reset-pin/`

Reset PIN using the token sent via email.

**Request:**
```json
{
  "token": "a1b2c3d4e5f6...",
  "new_pin": "1234"
}
```

**Response (200 OK):**
```json
{
  "detail": "PIN reset successful."
}
```

**Error Response (400 Bad Request):**
```json
{
  "detail": "Invalid or expired reset token."
}
```

---

### Password Reset

#### `POST /forgot-password/`

Request a password reset link to be sent to the user's email. Generates a random 64-character hex token (not Django's deterministic token generator) to avoid collisions on serverless platforms.

**Request:**
```json
{
  "email": "cascallensteve@gmail.com"
}
```

**Response (200 OK):**
```json
{
  "detail": "Password reset email sent successfully.",
  "email": "cascallensteve@gmail.com"
}
```

---

#### `POST /reset-password/`

Reset password using the token sent via email.

**Request:**
```json
{
  "token": "a1b2c3d4e5f6...",
  "new_password": "NewSecurePass123!"
}
```

**Response (200 OK):**
```json
{
  "detail": "Password reset successful."
}
```

---

### Token Refresh

#### `POST /api/token/refresh/`

Refresh an expired access token using a valid refresh token.

**Request:**

```json
{
  "refresh": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9..."
}
```

**Response (200 OK):**

```json
{
  "access": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9..."
}
```

## Data Models

### User

| Field | Type | Description |
|-------|------|-------------|
| `id` | AutoField | Primary key |
| `email` | EmailField | Unique, used as username |
| `username` | CharField | Unique username |
| `first_name` | CharField | First name |
| `last_name` | CharField | Last name |
| `password` | CharField | Hashed password |
| `pin` | CharField | Hashed PIN (nullable) |
| `pin_setup_complete` | BooleanField | True when PIN is set |
| `failed_login_attempts` | PositiveIntegerField | Consecutive failed attempts |
| `lockout_until` | DateTimeField | Account lockout expiry |
| `profile_picture` | URLField | Profile image URL |
| `created_at` | DateTimeField | Account creation timestamp |
| `updated_at` | DateTimeField | Last profile update timestamp |
| `is_active` | BooleanField | Django user active flag |
| `is_staff` | BooleanField | Django admin access |
| `is_superuser` | BooleanField | Django full admin access |

---

### PinResetToken

| Field | Type | Description |
|-------|------|-------------|
| `id` | AutoField | Primary key |
| `user` | ForeignKey | Related user (CASCADE delete) |
| `token` | CharField (64) | Unique random hex token |
| `created_at` | DateTimeField | Token creation timestamp |
| `expires_at` | DateTimeField | Token expiry (1 hour) |
| `used` | BooleanField | True when token has been used |

## Security Features

### Account Lockout

- **5 failed attempts** (password or PIN) triggers a **1-minute lockout**
- During lockout, all login attempts return:
  ```json
  {
    "detail": "Account locked. Try again in 45 seconds.",
    "lockout_remaining": 45
  }
  ```
- Failed attempts reset on successful login

### PIN Security

- PINs are **hashed** using Django's password hashers
- PIN must be **4-6 numeric digits**
- PIN login requires **email + PIN** (no standalone PIN entry)
- PIN can only be set when **already authenticated**

### No Registration

- No public registration endpoint
- Users are created via:
  - Django admin panel
  - `python manage.py seed_users` command

### JWT Tokens

- **Access token**: 12 hours lifetime
- **Refresh token**: 7 days lifetime
- Tokens include custom claims: `email`, `full_name`
- Refresh tokens are blacklisted on logout
